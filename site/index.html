skry @production

Everything you need to see, nothing to install

One SSH session per host, one small read-only shell script per tick. Everything else happens on your machine.

∅Agentless

No daemon, no copied binary, no temporary files, no sudo. Close skry and nothing is left behind.

r/oRead-only

skry only reads /proc and runs inspection commands. It has no way to run arbitrary commands on your fleet — on purpose.

🔒Secure by default

Honours known_hosts, refuses unknown or changed host keys, uses your agent and keys, never stores passwords.

▦Fleet view

Tiles coloured by health with CPU, memory, disk and load. Sort, filter, spot the problem at a glance. One broken host never blocks the others.

⌕Host details

Per-core CPU, memory and swap, network and disk I/O, filesystems, top processes, Docker/Podman containers, failed systemd units.

⏪Time travel

24 hours of local history, downsampled automatically. Scrub back and see the fleet — or one host — as it was.

⚑Security pulse

Failed SSH logins, pending security updates, ports outside your allowlist, TLS certificates about to expire.

◆Baselines

Learns what is normal for each host, per hour of day, and flags what is unusual for that host.

🔔Alerts

Slack, Discord and JSON webhooks with deduplication, cooldown, escalation and "resolved" messages.

📸Incident snapshots

Press s to capture the full state as Markdown and JSON — for the ticket, the post-mortem or the chat.

⇄Web + Prometheus

skry serve adds a read-only live dashboard and a /metrics endpoint for Grafana.

1One binary

A single file for Linux (static), macOS and Windows. Works with Debian, Ubuntu, RHEL/Rocky/Alma and Alpine servers.

How it works

The same SSH you already use. Nothing new to open, install or trust.

Connect

skry reads your ~/.ssh/config, verifies the host key against known_hosts and logs in with your agent or key — through bastions with ProxyJump if needed.

Read

Every two seconds it runs one short POSIX sh script that prints a few /proc files and the output of df, ps, ss… then exits.

Understand

On your machine skry turns counters into rates, checks thresholds and baselines, raises alerts and draws the picture.

What actually runs on your server

Print the exact script any time with skry script --all. An excerpt:

# one command per tick, POSIX sh, read-only
LC_ALL=C; export LC_ALL
m stat
grep -E '^(cpu|btime|procs_)' /proc/stat
m meminfo
cat /proc/meminfo
m df
$T df -P -k -l 2>/dev/null
m ports
ss -tlnH 2>/dev/null || netstat -tln 2>/dev/null
m end

Promises you can verify

  • No writes. Integration tests check that a monitored host's files are unchanged after collection.
  • No fleet-wide command execution. The only user input that reaches a shell is a validated unit name.
  • No surprises. Missing tools or permissions show as n/a, never as errors or false "all clear".
  • No passwords. Keys only; passphrases are used once and forgotten.
  • No telemetry. Data goes only where you send it.

Answers in one line

Beyond the live view, skry answers the questions you ask during a busy day.

# watch a group from your config file
skry @production

# one sample as JSON, for scripts
skry @production --once --json | jq '.[] | {name, status}'

# who listens on 5432? where does nginx run? is the timer healthy?
skry find port 5432 @production
skry find proc nginx @production
skry find service certbot.timer @production

# security pulse, incident snapshot, web dashboard + /metrics
skry security @production
skry snapshot @production --post
skry serve @production
